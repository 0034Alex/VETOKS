# VETOKS — план реализации

## 1. Стек

- **Frontend (Mini App + сайт + PWA)** — Next.js (App Router), один кодбейз,
  общие компоненты. Mini App — это тот же сайт, открытый внутри Telegram
  WebView через `@telegram-apps/sdk`, плюс адаптация под Telegram-тему и
  кнопки. PWA — `manifest.json` + service worker поверх того же сайта.
- **CRM** — отдельное Next.js-приложение (отдельный Vercel-проект), общий
  Supabase-бэкенд, но свой UI и роли доступа (модератор / амбассадор /
  финансист / суперадмин).
- **База данных / бэкенд** — Supabase (Postgres + Auth + Storage + Realtime
  для live-рейтинга и live-дуэлей + Edge Functions для платёжных вебхуков).
- **Хостинг** — Vercel (3 проекта: `vetoks-app`, `vetoks-site` можно
  объединить с app, `vetoks-crm`).
- **Репозиторий** — один монорепозиторий (pnpm workspaces / Turborepo),
  чтобы общие типы БД и UI-кит не дублировались между Mini App и CRM.

```
vetoks/
├── apps/
│   ├── web/              # Next.js: сайт + Mini App + PWA (один кодбейз)
│   └── crm/               # Next.js: внутренняя админка
├── packages/
│   ├── ui/                 # общие компоненты (кнопки, карточки, цвета)
│   ├── db-types/           # типы, сгенерированные из supabase (supabase gen types)
│   └── config/              # eslint/tsconfig/tailwind общие конфиги
├── supabase/
│   ├── schema.sql            # см. supabase/schema.sql
│   └── migrations/            # последующие миграции (после первой накатки схемы)
└── docs/
```

## 2. Порядок разворачивания у вас (по факту, не абстрактно)

1. Создать новый GitHub-репозиторий, залить эту структуру.
2. Создать новый проект в Supabase → выполнить `supabase/schema.sql` в SQL
   Editor → сохранить `SUPABASE_URL` и `SUPABASE_ANON_KEY`/`SERVICE_ROLE_KEY`.
3. Создать бота в @BotFather → получить токен → настроить Mini App URL.
4. Два проекта в Vercel (`web`, `crm`), в каждый — переменные окружения из
   Supabase.
5. Домен: сайт на основной домен, Mini App может открываться либо через
   `t.me/vetoks_bot/app`, либо на поддомене.

## 3. Дизайн-токены (чёрный / золото / белый)

Чистый чёрный на весь фон + чистое золото читаются тяжело и быстро
приедаются на длинных лентах контента, поэтому смягчаю оттенки и добавляю
два вспомогательных цвета для статусов/фона карточек — без них не собрать
читаемый UI (ошибки, успех, вторичный фон):

| Токен | HEX | Назначение |
|---|---|---|
| `--bg-primary` | `#0B0B0D` | основной фон (не чистый #000 — мягче для глаз) |
| `--bg-surface` | `#161618` | фон карточек/панелей поверх основного фона |
| `--gold` | `#C9A227` | акцент: кнопки, короны, лидеры рейтинга |
| `--gold-soft` | `#E8D48A` | второстепенный золотой (иконки, обводки) |
| `--white` | `#F5F5F2` | основной текст (не чистый #FFF — меньше контрастная усталость) |
| `--muted` | `#8A8A8E` | второстепенный текст |
| `--success` | `#3FA76B` | успех / рост в рейтинге |
| `--danger` | `#C24747` | ошибки / дисквалификация |
| `--accent-rose` | `#B76E79` | эхо "розы" из каталога подарков, для мелких акцентов в UI подарков |

Шрифт: заголовки — с чуть увеличенным трекингом (ощущение "премиальности"),
основной текст — нейтральный geometric sans (Inter/Manrope) для читаемости
на длинных лентах контента.

## 4. Что включаем на старте, а что — за флагом (без потери работы)

Вся схема БД уже покрывает все механики. Часть функций на старте будет
скрыта фичефлагом на уровне конфига региона/сезона, а не удалена — это не
"недоделка", а способ не показать зрителям, скажем, VIP-подписки в первый
же день, если платёжный провайдер для этого ещё не подключён. Список того,
что реально требует внешней интеграции до включения (не зависит от кода):

- Приём платежей (подарки/голоса) — нужен подписанный договор с эквайрингом
  или СБП до первой транзакции.
- Выплаты участницам — нужен их статус самозанятой/ИП, иначе даже готовый
  код выводить деньги не сможет легально.
- Kids — нужен процесс сбора согласия родителей, прежде чем открывать
  регистрацию.

Всё остальное (голосование, рейтинг, рефералка, контент-лента, дуэли,
челленджи, бусты, достижения, зал славы, CRM для модерации и амбассадоров)
можно кодить и включать сразу.
